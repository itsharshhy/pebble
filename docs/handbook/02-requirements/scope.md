# Scope
*Phase: Requirements · What's in, what's out, and how to handle new ideas without losing focus.*

## v1 scope
| In | Out (for now) |
|---|---|
| Add a worry (one line) | Accounts and login |
| Check-back date | Cloud sync |
| Check-back with 3 answers + Let it go + Undo | AI of any kind |
| Garden summary | Charts and mood graphs |
| Export, import, delete all | Notifications |
| Optional feeling word, next step, breath pause | Sharing or social |
| Light and evening palettes; reduced motion | Mobile app-store builds |
| Settings + About & safety | Translations |

**Screen budget for v1:** 5 screens (Today, New worry, Check-back, Garden, Settings) plus the
optional breath pause. Adding a screen requires removing one or a strong case against the Principles.

## How to handle a new idea (change control)
New ideas are good. Acting on them immediately is how projects never finish.
1. **Write it down** as a GitHub Issue with the label `idea`. That alone quiets the urge (the same mechanism as [Science S2](../00-foundation/science.md#s2)).
2. **Don't discuss it** until the current loop ships.
3. At the **monthly review**, test it against the [Principles](../00-foundation/principles.md) and the [Calm Audit](../05-testing/calm-audit.md).
4. If it passes, give it a MoSCoW priority and a version in the [Roadmap](../01-planning/roadmap.md).
5. If it fails, close it kindly with the reason. That's a finished decision, not a lost idea.

## Questions to ask about any idea
- Which persona needs this, and how badly?
- Does it add a screen, a choice, or a notification? (Each one costs calm.)
- Could it make someone more anxious?
- Is there evidence, and what strength?
- What's the smallest version of it?

## Done when
The current version's In/Out table is unchanged since the loop started, or every change went through change control.
